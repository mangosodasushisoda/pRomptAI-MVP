# 🚀 pRomptAI (MVP)
> **"Stop coding by blocks, start thinking in logic."**
> スクラッチの「操作の難解さ」を排し、自然言語による対話を通じてプログラミング的思考（ロジック）をダイレクトに実行環境へ繋げる実験的プロジェクト。

---

## 💡 プロジェクトの背景 (Vision)
既存のビジュアルプログラミング（Scratch等）は、本来学ぶべき「論理の構築」の前に、特有のUI操作やブロックの組み合わせ方に習熟する必要がありました。本プロジェクトは、その「UIの壁」と「英語の壁」をAIで取り払い、初心者が**自分の母国語で考えたロジックがそのまま動く感動**を最短距離で提供することを目指しました。

### 📜 背景 (The Backstory)
4年前、初めて触れたスクラッチは自分にとって「苦痛」でしかなかった。操作も概念もわからず、挫折しそうな日々が続いた。それでも「プログラミングができるようになりたい」という執念だけで続けてきた。...まあ好きだけどね？悪く言ってるけど別にスクラッチに対して悪い印象はないからね？

その時の自分に「これがあれば救われたのに」と思えるツールを、今の自分の技術（AIとC++/JS）で形にしたのが、この pRomptAI です。

---

## 🛠 技術スタックと設計思想

### 1. Local-First AI Architecture
* **LM Studio (Local LLM) 統合:** クラウドAIのAPIコスト問題を回避し、プライバシーとオフライン実行を担保。「金がない」という制約を、**「個人のPCリソースを最大限に活用するエッジコンピューティング」**という強みに転換。
* **Zero-Latency Design:** 通信制限に左右されないローカル環境での開発。

### 2. Natural Language Compilation (NLC)
* **意図的な「手動コンパイル」ボタン:**
  コンパイル成功率が100%ではない現状を踏まえ、あえて自動実行（即コンパイル）ではなく、ボタン押下による実行方式を採用。これにより、AIが生成したコードに対して**「やり直し（再生成・再試行）」**をユーザーが主体的に選択できる、失敗を前提とした柔軟な開発サイクルを実現。
* **Implicit Context Execution:** 複雑な初期設定を隠蔽し、初心者が「本質的なロジック」だけに集中できるサンドボックス環境を提供。

## 📝 初期構想メモ (Vision Document)

### 1. なぜ作るのか？ (Motivation)
* **既存ツールの壁:** スクラッチで育ってきたが、最初は操作方法の意味が全くわからず苦痛だった。その経験を繰り返させないため。
* **言葉の壁:** 日本語でロジックを組み立て、英語の構文に邪魔されずに学びたい。

### 2. 実現したいこと (Core Concepts)
* **「ヒント」としてのAI:** AIはあくまでガイド。全自動生成は極力避け、倫理的思考力を育てることを優先。
* **ステップアップ支援:** 日本語コードに慣れた後、C++やRustなど実用言語への移行をAIがサポートする。

### 3. 開発における自分ルール (Guidelines)
* **AIを過信しない:** コンパイル失敗を織り込んだUI設計（やり直しボタン等）。
* **学習者の「脳」を育てる:** スクラッチが最初にわからなかった時のような苦労を、「自分でロジックを言語化する楽しさ」に変える。

## 🛠 実行方法
1. LM Studio等のローカルサーバーを起動。
2. 本リポジトリの `index.html` をブラウザで開く。
3. AIにやりたいことを伝え、コンパイルボタンを押してコードが走る快感を体験する。
